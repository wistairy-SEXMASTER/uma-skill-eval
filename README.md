# ウマ娘 スキル評価点 査定

`master.mdb` から **スキル名・評価点・スキルポイント(SP)** を抽出し、査定用の一覧表示と合計計算を行うツールです。

`index.html` をブラウザで開くだけで使えます（ローカルファイルのまま動作します）。

## できること

- スキル名・説明・スキルIDでの検索（スペース区切りでAND）
- 種別（ノーマル／レア／固有／継承固有／進化）で絞り込み
- カテゴリ（コース・馬場・天候／スタート・序盤／中盤／終盤／コーナー・直線／固有）で絞り込み
- SP取得可能なスキルのみ表示
- マイナス系スキルの表示切り替え（初期状態は非表示）
- 選択中スキルのみ表示
- 評価点・SP・上昇評価点・上昇効率・下位込みSP・総合効率でソート
- 行クリックでスキルを選択し、合計評価点・合計SP・総合効率をリアルタイム計算
- 同じグループのスキルは、最も上位の1つだけを合計に加算
- 上位スキルを選択すると、同じグループの下位スキルも自動選択
- 選択したスキルをCSV出力（Excel向け UTF-8 BOM）
- ヒントLv（0〜5）をスキルごとに設定し、割引後SP・効率を再計算
- ヒントLvを一括リセット（全スキルをLv0に戻す）
- 切れ者の有無を設定し、ヒントLvのSP割引に −10% を加算
- 距離適性・脚質適性（S〜G）を設定し、スキル評価点に適性倍率を適用
- 固有レベル（1〜6）を設定し、固有スキルを「Lv × 170」で計算
- ウマ娘（カード）を選択して、距離・脚質の初期適性を自動設定
- ウマ娘選択時に、そのカードが最初から持つ金スキルと進化先スキルを表示し、ドロップダウンで通常 / 進化先を選択
- シナリオを選び、そのシナリオで選択可能な進化スキルを一覧表示して選択
- 距離・馬場・脚質の適性フィルタ（いずれか1つ一致で表示）
- 効果カテゴリ（速度・加速・回復・緑・デバフ・位置取り・視野・ゲートなど）で絞り込み
- 獲得SP予算から合計評価点が最大になるスキル組み合わせを計算
- 画像認識（スクリーンショット / 画面キャプチャ）でスキル名・ヒントLv・SPを読み取り
- ウマ娘の名前・衣装名を画像から認識し、初期適性を自動設定
- 複数画像をスキルごとに統合（スクロールしながらの取り込みに対応）
- 選択状態・ヒントLv・査定設定・フィルタ・予算をブラウザの `localStorage` に保存

## 使い方

1. `C:\Users\wister2\apps\uma-skill-eval\index.html` をブラウザで開く
2. 必要に応じて「ウマ娘」を選び、初期適性を自動設定する
3. 必要に応じて進化パネルのドロップダウンで、各金スキルの「通常 / 進化先」を選ぶ
4. 必要に応じて「シナリオ進化」でシナリオを選び、そのシナリオの進化先を選ぶ
5. 検索欄やフィルタ、効果カテゴリのチップでスキルを絞り込む
6. 行をクリックしてスキルを選択する
7. 必要に応じて「査定設定」で、切れ者・固有Lv・距離適性・脚質適性を設定する
8. 必要に応じて一覧の「ヒントLv」列で、スキルごとのヒントLvを変更する
9. 必要に応じて「ヒントLvリセット」で全スキルのヒントLvを0に戻す
10. 画面下部に合計評価点・合計SP・総合効率が表示される
11. 必要に応じて「獲得SPから最大評価を計算」で予算内の最適な組み合わせを求める
12. 必要に応じて「画像認識」でスクリーンショットからスキル名・ヒントLv・ウマ娘を読み取る
13. 必要に応じて「CSV出力」を押す

> `data/skills.js` を相対パスで読み込むため、`index.html` をダブルクリックして開いても動作します。

| 列 | 内容 |

| `group_rate` | 1=基本、2=上位、3=最上位、-1=マイナス系 |
| `prereq_sp` | 下位スキル取得に必要なSPの合計 |

| `category` | スキルカテゴリ（下記） |
| `category_label` | カテゴリの表示名 |
| `purchasable` | SPで取得可能か（`sp` が存在するか） |
| `available` | 期間限定スキルが現在有効か |
| `description` | 説明文（`text_data.category = 48`） |
| `start_date` / `end_date` | 期間限定スキルの開始・終了（Unixタイムスタンプ） |
| `apt_distance` | 距離適性の条件（`1`=短距離、`2`=マイル、`3`=中距離、`4`=長距離。`/` はOR） |
| `apt_style` | 脚質適性の条件（`1`=逃げ、`2`=先行、`3`=差し、`4`=追込。`/` はOR） |
| `apt_ground` | 馬場の条件（`1`=芝、`2`=ダート。`/` はOR） |
| `apt_source` | 適性条件の取得元（`tag`=説明文の＜＞、`condition`=発動条件、空=適性条件なし） |

### ヒントLv

ヒントLvによるSP減少率は次のとおりです。ゲーム内と同様に、割引後のSPは**小数点以下切り捨て**で計算します。

| ヒントLv | 減少率 | 170SPの例 |
| --- | ---: | ---: |
| Lv0 | 0% | 170 |
| Lv1 | 10% | 153 |
| Lv2 | 20% | 136 |
| Lv3 | 30% | 119 |
| Lv4 | 35% | 110 |
| Lv5 | 40% | 102 |

- 一覧の「ヒントLv」列で、スキルごとにLvを設定します（初期値はLv0）。
- 設定はスキルIDごとに `localStorage` へ保存され、次回開いたときも復元されます。
- 上位スキルの「下位込みSP」は、下位スキルそれぞれに設定したヒントLvで割引したSPを合計します。下位スキルのヒントLvを変えると、上位スキルの下位込みSPにも反映されます。

CSV出力では、ヒント割引前と割引後の両方を出力します。

| 列 | 内容 |
| --- | --- |
| `sp_base` / `sp` | そのスキル単体のSP（割引前 / 割引後） |
| `hint_level` | 適用したヒントLv |
| `total_sp_base` / `total_sp` | 下位込みSP（割引前 / 割引後） |
| `prereq_sp_base` / `prereq_sp` | 下位スキル分のSP（割引前 / 割引後） |
| `efficiency` | 上昇効率（割引後SPで計算） |
| `total_efficiency` | 総合効率（割引後SPで計算） |
| `eval_base` / `eval_point` | 適性倍率・固有Lv適用前 / 適用後の評価点 |
| `aptitude_distance` / `aptitude_style` / `aptitude_ground` | スキルの適性条件 |
| `aptitude_multiplier` | 適用した適性倍率（固有・継承固有は1） |
| `aptitude_source` | 適性条件の取得元 |
| `unique_level` / `fast_learner` | 計算時の固有Lv / 切れ者有無 |

### 切れ者

- 「査定設定」の「切れ者」をオンにすると、ヒントLvの減少率に **−10%** を加算します。
- 例: Lv5（−40%）＋切れ者 = **−50%**、Lv0＋切れ者 = **−10%**。
- 割引後SPはヒントLvと同じく小数点以下切り捨てです。
- 切れ者は選択中の全スキルに適用されます。

### 適性倍率

| 適性 | 倍率 |
| --- | ---: |
| S / A | 1.1 |
| B / C | 0.9 |
| D / E / F | 0.8 |
| G | 0.7 |

- 「査定設定」の距離適性（短距離・マイル・中距離・長距離）と脚質適性（逃げ・先行・差し・追込）を設定します。初期値はすべてAです。
- **芝・ダートは倍率に影響しません。** 距離適性と脚質適性だけが対象です。
- 説明文の ＜中距離/長距離＞ のように **`/`** で区切られた条件は、同じカテゴリのORです。**良い方の適性**を使用します。
- ＜先行・中距離＞ のように **`・`** で区切られた条件は、異なるカテゴリのANDです。**両方の倍率を乗算**します。
- 例: 先行A・中距離A → 1.1 × 1.1 = **1.21倍**。先行G・中距離G → 0.7 × 0.7 = **0.49倍**。
- 倍率適用後の評価点は四捨五入します（uma-tools と同じ単精度積算）。
- 固有・継承固有スキルは適性倍率の対象外です。

### 固有レベル

- 「査定設定」の固有Lv（1〜6）は、種別が「固有」のスキルに適用します。
- 固有スキルの評価点 = **固有Lv × 170**（Lv1=170、Lv6=1,020）。適性倍率は適用しません。
- **継承固有**スキルは一律 **180** です。
- **進化**スキルは通常スキルと同じく、評価点に適性倍率を適用します。

### ウマ娘の初期適性

- 「ウマ娘」でカードを選ぶと、`card_rarity_data` の距離適性・脚質適性を「査定設定」に自動反映します。
- 芝・ダート適性はカード情報として表示しますが、評価点倍率には影響しません。
- 手動で適性を変更した場合は、その値が優先されます。「初期適性に戻す」でカードの値に再設定できます。
- カードの適性は `data/skills.js` の `cards` に収録しています（`card_data` + `card_rarity_data`）。

### 適性フィルタ

- 「適性フィルタ」の距離・馬場・脚質チップでスキルを絞り込みます。
- スキルの適性条件のうち、**いずれか1つでも一致**すれば表示します。例: ＜短距離・芝＞ のスキルは「短距離」または「芝」のどちらかを選べば表示されます。
- 「汎用を含む」がオンの場合、適性条件のないスキルは常に表示します。オフにすると除外します。
- 「クリア」でフィルタを解除します。

### 効果カテゴリ

- 「効果」のチップで、スキルを**速度・加速・回復・緑・デバフ・位置取り・視野・ゲート・特殊・その他**に分類して絞り込みます。
- 分類は `skill_data.ability_type_1_1`（主効果）を基準にします。複数の効果を持つスキルは、最初の効果（`ability_type_1_1`）のカテゴリに入ります。
- 「すべて」で全カテゴリの表示 / 非表示を切り替えます。

### 進化スキル

- 進化の対象は、**育成ウマ娘が最初から持つ金スキル**（`available_skill_set` の `rarity = 2`）です。固有スキルは進化の対象外です。
- 「ウマ娘」を選ぶと、そのカードの金スキルごとに、**進化先スキルを選ぶドロップダウン**を表示します。
- 進化スキルの対応は `skill_upgrade_description` を使用します。`skill_upgrade_description.rank` が `available_skill_set.need_rank` に対応し、同じ rank の金スキルが進化元になります（例: スペシャルウィーク rank 3 → 食いしん坊 → はらぺこ大将）。
- ドロップダウンで「通常: 金スキル」または「進化: 進化先スキル」を選択します。同じ金スキルにつき1つだけ選択でき、別の選択肢に切り替えると前の選択は自動的に外れます。
- 「未選択」を選ぶと、その金スキルの選択を解除できます。
- 進化スキルを選ぶと、**進化元の金スキルのSP（下位込み）**をコストとして合計SPに含めます。進化スキル自体の追加SPはありません。
- 進化スキルのSPは進化元の金スキルのヒントLv・切れ者を反映します。進化スキル側のヒントLv欄は `—` になります。

### シナリオ進化

- 「シナリオ進化」の欄で育成シナリオを選ぶと、そのシナリオで選択可能な進化スキルを一覧表示します。
- シナリオ別の進化対応は `skill_upgrade_speciality`（`scenario_id` / `base_skill_id` / `skill_id`）を使用します。
- 一覧には「進化元の金スキル → 進化先スキル」と評価点・SPを表示します。「選択」でその進化先スキルを選択できます。
- 同じ金スキルに複数の進化先がある場合、カード固有進化も含めて**1つだけ**選択できます。別の進化先を選ぶと前の選択は自動的に外れます。
- シナリオ進化のSPも、進化元の金スキルのSP（下位込み）を使用します。

### ヒントLvの一括リセット

- 「ヒントLvリセット」を押すと、すべてのスキルのヒントLvを **0（割引なし）** に戻します。
- 個別のヒントLv設定は `localStorage` からも削除されます。

### 最大評価の計算

- 「獲得SPから最大評価を計算」にSP予算を入力し、「計算」を押すと、予算内で合計評価点が最大になるスキルの組み合わせを求めます。
- アルゴリズムは**グループ単位の多重選択ナップサック**です。同じグループは最上位1つだけを選び、下位スキルのSPもコストに含めます。
- コストは**下位込みSP**（ヒントLv・切れ者を反映）、価値は**適性倍率込みの評価点**です。
- **選択中のスキルがある場合は、その選択だけを候補にします。** 選択がない場合は、「現在の絞り込みを使用」がオンなら検索・種別・カテゴリ・適性フィルタの結果、オフなら全スキルを候補にします。
- 固有・継承固有などSPで取得できないスキルは計算対象外です。
- 「結果を選択に反映」で、計算結果のSP取得スキルを選択状態にします。SP対象外の選択は保持します。
- 計算量の目安: `グループ数 × 予算 × グループ内候補数`。予算は最大20,000SPまでです。

### 画像認識（OCR）

- 「画像認識」パネルでスクリーンショットからスキル情報やウマ娘を読み取ります。
- 入力方法:
  - 「画像を追加」でファイル選択（複数可）
  - ドラッグ＆ドロップ
  - 「クリップボードから貼り付け」
  - 「画面キャプチャ開始」でゲーム画面を共有し、「この画面を取り込む」
  - 「変化時取り込み」でスクロールのフレーム変化を検出し、スクロールが止まった画面を自動保存（最大120枚）
- 変化時取り込みは250msごとにフレームを比較し、変化後およそ0.5秒安定した画面を保存します。同一画面はハッシュでスキップします。
- 変化時取り込みは**画面全体**と**スキル一覧領域**の両方を比較します。`MediaStreamTrackProcessor` が使える環境では動画フレームを直接読み取るため、タブが裏でも反応しやすくなっています。
- 感度（高/中/低）で変化検出の閾値を調整できます。取り込み中は「画面 diff / 一覧 diff / 取り込み枚数」を表示します。ゲーム画面は共有画面の左側に置いてください。
- **画面キャプチャはChrome/Edgeで開いた場合のみ利用できます。** OpenCode内蔵ブラウザ（Electron）では `getDisplayMedia` が権限拒否されるため、「画像を追加」または「クリップボードから貼り付け」を使ってください。「URLをコピー」でChrome/Edge用のURLを表示できます。
- **100件規模のヒント**にも対応しています。画面を分けて取り込むと、スキルID単位で重複を統合します。
- **高速モード**（初期オン）では、OCRを1パス・1400px・2並列ワーカーで実行します。オフにすると二値化バリアントも試すため精度重視になります。
- 行の位置（bbox）からスキル名とヒントLvを同じ行としてグループ化し、対応付けの精度を上げています。
- スキル一覧の領域を自動クロップし、Tesseractの `PSM 11`（スパーステキスト）で認識します。これにより、画像全体をOCRするよりスキル名が読み取りやすくなります。
- オレンジ色のヒントバッジを色検出し、専用の小さなOCRで `Lv3` / `30%OFF` を読み取ります。メインのOCRがバッジを苦手にしてもヒントLvを取得できます。
- ゲーム内フォント（**UMAMUSUME-RodinWanpaku Pro EB**）を `resources.assets` から抽出し、候補スキル名の画像照合に使用します。これにより `○` / `◎` / `×` などの紛らわしい表記やOCRの文字誤りを補正します。
- フォントは `assets/umamusume-font.ttf` に保存します。ライセンス上Gitにはコミットしません。`py extract_skills.py` 実行時に自動抽出します（`pip install UnityPy` が必要）。フォントが無い場合もOCRは動作します（画像照合のみスキップ）。
- **スキル取得画面モード**:
  - スキル名を辞書とファジーマッチングし、オレンジのヒントバッジからヒントLvを読み取ります。SPコストはOCRしません。
  - ヒントLvが読めない場合は、バッジの「30%OFF」などから推定します。
  - 複数画像の結果をスキルIDごとに統合します。スクロールしながら複数枚取り込めます。
  - 結果表のヒントLvは手動で修正できます。
- **ウマ娘の適性モード**:
  - キャラ名と衣装名を認識し、該当カードの初期適性を設定します。
  - 同じキャラの衣装が複数ある場合は候補から選択できます。
- OCRは画像全体を正規化して認識するため、固定座標に依存せず、ウィンドウサイズが変わっても動作します。
- OCRエンジンは [Tesseract.js](https://tesseract.projectnaptha.com/)（`jpn+eng`）をブラウザ内で実行します。初回のみCDNからエンジンと日本語データを取得します（画像自体は外部送信しません）。
- 認識結果は誤ることがあります。必ず結果表を確認し、必要に応じて修正してください。

### OCR精度の改善方法

現状は「Tesseract OCR + スキル辞書 + ゲーム内フォント画像照合 + ヒントバッジ色検出」のハイブリッドです。さらに精度を上げる方法は次のとおりです。

1. **実画像のラベル付きデータを集める**
   - 1つのウィンドウサイズにつき、スキル画面20〜50枚
   - 各画像に「スキル名 / ヒントLv」の正解を付ける
   - これを回帰テストと閾値調整に使う

2. **ゲーム内フォントで合成データを作る**
   - 全2,189スキル名をゲームフォントで描画
   - サイズ・背景色・ぼかし・JPEG圧縮・明るさを変えて増やす
   - フォント画像照合の閾値調整や、軽量な文字列分類器の学習に使う

3. **Tesseractを微調整する（tesstrain）**
   - 実画像と合成画像から行画像＋正解テキストを作る
   - `tesstrain` で `jpn` モデルをLSTM微調整する
   - 数千〜数万行と数時間の学習が必要
   - 効果は大きいが、環境構築と学習コストが高い

4. **訂正キャッシュ／アクティブラーニング**
   - ユーザーが結果を修正したら「画像ハッシュ＋OCRテキスト → 正しいスキルID」を保存
   - 同じ・似た画像では修正結果を再利用
   - 低信頼度の行だけ確認を求める

5. **ヒントLv専用の分類器**
   - オレンジバッジを色検出し、Lv1〜5の数字だけを小さな分類器で判定
   - バッジは「Lv3」「30%OFF」の2パターンがあるため、数字と%を別々に扱うと安定する

6. **データ拡張**
   - ウィンドウサイズ、UIスケール（100/125/150%）、解像度、JPEG品質、背景の明るさを変える

7. **評価指標**
   - スキル名 top-1 / top-3 正解率
   - ヒントLv一致率
   - 誤検出率（存在しないスキルを出す割合）

まずは**実画像50枚程度＋ゲームフォントの合成データ**で、フォント照合とバッジOCRを調整するのが最短です。Tesseractの微調整は、その後に必要になったタイミングで検討するのが現実的です。

## 計算式

```text
適性倍率（通常・進化） = 距離倍率 × 脚質倍率（該当する条件のみ）
評価点（通常・進化）   = round(grade_value × 適性倍率)
評価点（固有）         = 固有Lv × 170
評価点（継承固有）     = 180
上昇評価点 = 評価点 - 下位スキルの評価点（同じ査定設定で計算）
上昇効率   = 上昇評価点 / そのスキル単体のSP（ヒント割引後）
下位込みSP = そのスキル単体のSP + 下位スキルのSP合計（各スキルのヒントLvで割引）
総合効率   = 評価点 / 下位込みSP

割引後SP = floor(割引前SP × (1 - ヒントLvの減少率 - 切れ者10%))
```

### グループの扱い

同じ `group_id` のスキルは下位→上位の関係です。たとえば `右回り○` → `右回り◎` → `右回りの鬼` は同じグループです。

- ビューアで同じグループの複数スキルを選択した場合、`group_rate` が最も大きい1つだけを合計に加算します。
- 下位スキルは「集計外」と表示されます。
- 上位スキルを選択すると、その `total_sp`（下位込みSP）が合計SPに加算されます。
- **上位スキルを選択すると、同じグループの下位スキルも自動的に選択されます。** 例: 「決意の直滑降」を選ぶと「直滑降」も選択されます。
- 下位スキルだけを選択した場合は、そのスキル単体のSPが加算されます。

## 注意事項

- 評価点は基本値 `skill_data.grade_value` に、設定した**適性倍率**を適用して計算します（S/A=1.1、B/C=0.9、D/E/F=0.8、G=0.7）。
- 固有スキルは**固有Lv × 170**で計算します（継承固有は一律180）。固有Lvは「査定設定」で1〜6を指定してください。
- ヒントLvによるSP割引（Lv1 −10% 〜 Lv5 −40%、小数点以下切り捨て）と、**切れ者 −10%** を実装済みです。
- 固有・進化スキルはSPでは取得できませんが、ビューアでは評価点だけを合計に加算します（「SP対象外の評価点」として表示）。
- ウマ娘の初期適性は `card_rarity_data` の値を使用します（レアリティ間で適性は共通です）。
- 最大評価の計算は、SPで取得できるスキルだけを対象にします。固有・継承固有などSP対象外のスキルは含みません。
- 画像認識は初回のみOCRエンジンと日本語データをCDNから取得します（ネット接続が必要）。画像自体は外部に送信されません。
- OCRの精度は画像の解像度・圧縮・UIの表示サイズに依存します。PNGのスクリーンショットを推奨します。認識結果は必ず確認してください。
- ゲーム内フォントは著作物のため、`assets/umamusume-font.ttf` はGitにコミットしません。各自のゲームファイルから `py extract_skills.py` で抽出してください。
- マイナス系スキル（`group_rate = -1` または評価点が負）は初期状態では非表示です。「マイナス系を含む」をオンにすると表示されます。
- 特殊スキル（ストーリー・イベント用）と期限切れスキルは `data/skills.js` には収録していません。
- ゲームのアップデートで評価点・SPが変わった場合は、`py extract_skills.py` を再実行してデータを更新してください。
- 本ツールはゲーム内の査定値を完全に再現するものではありません。スキル選択の比較・目安として使用してください。

## 開発メモ

- `out/skills.csv` は全2,223件、`out/skills_rating.csv` と `data/skills.js` は特殊・期限切れを除いた2,189件です。
- 抽出時点: 2026-11-07、DB更新: 2026-10-28。
- `apt_distance` / `apt_style` は説明文の＜＞タグから抽出します。タグがない一部の進化スキルは、発動条件の `distance_type` / `running_style` から補完します（単一条件のみ）。
- `apt_ground` は説明文タグと発動条件の `ground_type` から抽出します（絞り込み用。評価点倍率には未使用）。
- `effect_category` は `skill_data.ability_type_1_1`（主効果）から判定します。分類は `extract_skills.py` の `EFFECT_TYPE_LABELS` で変更できます。
- `data/skills.js` の `cards` には `card_data` と `card_rarity_data` から取得したウマ娘の初期適性を収録しています。
- `data/skills.js` には進化スキル用に次のデータも収録しています。
  - `cardInitialSkills`: `card_data.available_skill_set_id` → `available_skill_set` の初期スキル
  - `cardGoldSkillEvolutions`: `skill_upgrade_description` のカード別・金スキル → 進化スキル対応（`rank` = `need_rank`）
  - `scenarios`: `single_mode_scenario` と `text_data`（category 119）のシナリオ一覧
  - `scenarioEvolutions`: `skill_upgrade_speciality` のシナリオ別進化スキル
- `py extract_skills.py` を実行すると、`index.html` の `data/skills.js?v=...` も自動更新されます（ブラウザキャッシュ回避）。
- OCRは `index.html` 内で Tesseract.js v5（`jpn+eng`）をCDNから遅延読み込みします。画像はCanvasでグレースケール・コントラスト補正・Otsu二値化してから認識します。
- OCRの辞書は `data/skills.js` のスキル名と `cards` をそのまま使用します。スキルを追加した場合はデータ再生成だけで辞書も更新されます。
- `data/skills.js` は約1.5MBあります。`index.html` と同じフォルダ構成のまま使用してください。
- 検証:

```powershell
py verify.py
```

`verify.txt` に主要スキルの計算結果と、総合効率の上位スキルが出力されます。
